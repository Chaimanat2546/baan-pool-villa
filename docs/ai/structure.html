Maintenance Triggers

Update this file in the same change when any of these happen:

  • A route, route group, loading UI, not-found UI, or route handler is added, moved, renamed, or removed.
  • A feature folder, shared component family, shared helper module, or ownership boundary changes.
  • A new site setting, CMS table, Supabase migration pattern, public data contract, or admin API flow is introduced.
  • Cache tags, cache durations, revalidation paths, SEO helpers, contact helpers, pricing helpers, or image URL ownership changes.
  • The recommended targeted tests for a feature area change.

Top-Level Map

Path Role Notes
app/ Next.js App Router routes and route handlers Route files should stay thin and delegate UI/data logic to feature modules.
components/ Public, admin, layout, and small UI components Feature UI belongs in its feature folder; avoid top-level villa re-export wrappers.
lib/ Data access, normalization, validation, settings, SEO, cache, pricing, and shared helpers Prefer these helpers over ad hoc constants or duplicated transforms in components.
scripts/central-user-manager/ Tenant rollout utilities for Central User Manager The Auth metadata backfill is dry-run by default, reads the existing non-secret NEXT_PUBLIC_HOME_CONFIG_SUPABASE_URL owner plus the server-only SUPABASE_SECRET_KEY, requires the exact --apply --project-ref <ref> pair before writes, performs a complete Auth/profile identity and credential-fence preflight, preserves unrelated metadata and provenance, and emits only a redacted JSON-safe report. Profile reads select user_id,email,is_active,credential_version, require exact safe database version 1 for active and inactive rows, and use bounded user_id-ordered range pages. Every short profile page, including an empty first page, is followed by a one-row sentinel at its exact next offset; a found sentinel row fails closed instead of trusting a possibly server-capped page. Auth reads use explicit bounded pagination. Run the backfill only against an explicitly selected Tenant and never before reviewing its dry-run report. Retired Bearer validation and Auth-attestation helpers are not a provisioning or runtime protocol and must not be restored.
docs/central-user-manager/tenant-provisioning.md Thai operator runbook for per-Tenant RPC-only provisioning and cutover Owns the inactive gate, immutable canonical Tenant UUID, target-first Tenant deploy, webook Service Binding deployment to CentralUserManagerEntrypoint.executeOperation, binding-only list_users readiness, and disposable-user staging mutations. It requires empty public 404 for all legacy/bridge paths, retired-secret removal after cutover, explicit quarantine/read-only reconciliation, and no-Bearer rollback. The required schema order remains prepare migrations → dry-run backfill → approved apply + verify → enforcement migration → enable credential fence. The source-controlled migrations are not evidence that an online project has been changed.
supabase/ Schema migrations and seed data Migrations are source-controlled history; online project changes need minimal idempotent patch SQL. Public villa catalog reads require an explicit anon SELECT grant and read-only RLS policy on public.images; 20260730220000_restore_public_images_read_access.sql repairs clones that retained only the authenticated-admin image policy. For the admin credential fence, complete and verify the Auth metadata backfill before applying enforce_admin_credential_fence.
next.config.ts Next.js build/runtime configuration Image config keeps allowed remote hosts documented, uses the custom image loader from lib/aws-loader.ts instead of the built-in Next image optimizer, and applies the sitemap response cache header. AWS-origin sources and s3.ap-southeast-1.amazonaws.com/poolvillas.co.ltd objects receive width/quality transform params through the AWS loader; other validated HTTPS sources load directly with width/quality query params so current external catalog and CMS images do not break.
tests/ End-to-end and production smoke tests Unit and component tests usually live beside the touched feature in __tests__.
docs/ Agent specs, plans, and AI-facing structure docs This file lives at docs/ai/structure.html.

Admin Route Handlers

Shared admin authorization lives in lib/admin/home-config-auth.ts and lib/admin/route-helpers.ts: mutation origin checks run before Bearer parsing, then every parsed token is verified without a positive cache against both Supabase Auth claims and the current Auth user before the exact local admin profile fence is read. lib/admin/request-origin.ts owns origin matching and lib/admin/turnstile.ts owns Turnstile Siteverify. Keep route handlers focused on request parsing, validation, persistence, and cache invalidation.
