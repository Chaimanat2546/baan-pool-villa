Baan Pool Villa AI Structure Map

This document is the source of truth for repository structure, ownership, and common data flow. Use AGENTS.md for rules and this file for where things live.

Last reviewed: 2026-06-12. Next.js App Router route groups such as (home), (public), and (admin) do not appear in the public URL.

Maintenance Triggers

Update this file in the same change when any of these happen:

  • A route, route group, loading UI, not-found UI, or route handler is added, moved, renamed, or removed.
  • A feature folder, shared component family, shared helper module, or ownership boundary changes.
  • A new site setting, CMS table, Supabase migration pattern, public data contract, or admin API flow is introduced.
  • Cache tags, cache durations, revalidation paths, SEO helpers, contact helpers, pricing helpers, or image URL ownership changes.
  • The recommended targeted tests for a feature area change.

Top-Level Map

Path Role Notes
app/ Next.js App Router routes and route handlers Route files should stay thin and delegate UI/data logic to feature modules.
components/ Public, admin, layout, and small UI components Feature UI belongs in its feature folder; avoid top-level villa re-export wrappers.
lib/ Data access, normalization, validation, settings, SEO, cache, pricing, and shared helpers Prefer these helpers over ad hoc constants or duplicated transforms in components.
supabase/ Schema migrations and seed data Migrations are source-controlled history; online project changes need minimal idempotent patch SQL.
next.config.ts Next.js build/runtime configuration Image config keeps allowed remote hosts documented, disables the Next image optimizer globally so public images do not consume /_next/image transformations on Cloudflare Free, and applies the sitemap response cache header.
tests/ End-to-end and production smoke tests Unit and component tests usually live beside the touched feature in __tests__.
docs/ Agent specs, plans, and AI-facing structure docs This file lives at docs/ai/structure.html.

App Router Map

Root Files

Path URL Responsibility
app/layout.tsx All routes Root HTML/body shell, global metadata base, global CSS/font wiring, and revalidate = 0 so rendered App Router pages are produced on demand while explicit data caches remain tagged and time-based.
app/sitemap.ts /sitemap.xml Public sitemap using villa, guide CMS, legal page CMS, and site URL helpers. The sitemap response keeps a 24-hour route cache with revalidate = 86400 and a sitemap-specific Cache-Control header from next.config.ts; underlying villa, guide, and legal page reads keep their tagged data caches. Dynamic villa source failures should fail the sitemap route; guide or legal CMS failures can return a partial sitemap with static and villa routes so CI/build environments without CMS env do not fail. lastModified should only be emitted where upstream data has a trustworthy timestamp.
app/robots.ts /robots.txt Robots configuration.
app/globals.css All routes Tailwind v4 global styles and shared theme variables.

Public Routes

Path URL Delegates To
app/(public)/layout.tsx Public shell components/layout, resolved site settings, theme variables, contact config. The shell inherits root on-demand rendering and must not force force-dynamic because that would turn explicit data caches into no-store fetches.
app/(public)/(home)/page.tsx / components/villas/home/page, lib/seo.ts, lib/json-ld.ts; rendered output is on demand while guide, villa catalog, home-section, and site-settings reads come from tagged data caches. app/(public)/(home)/loading.tsx / loading UI components/villas/home/loading-skeleton.
app/(public)/search/page.tsx /search components/villas/search/page, villa listing helpers, landing first-page search metadata, and site-settings-backed public SEO defaults. The route resolves metadata through the search section SEO template before falling back to global SEO. Query-string filtering is intentionally not performed by the server route; the client reads the current URL, then requests bounded filtered pages from /api/houses when a deep link or interaction needs more results, so the public API does not expose the full catalog in one response.

app/(public)/villas/[id]/not-found.tsx /villas/:id missing villa UI Detail not-found experience.

Component Ownership

Path Owns Reuse Notes
components/villas/home Home page sections, CMS-driven home assembly, hero/articles/destination sections, TikTok block renderer (settings-driven, first-6 thumbnail preview with click-to-load player), villa rails, home skeletons, and minimal homepage client payloads. Use VillaRail, home shared helpers, and section header patterns before creating new section UI. Keep results incremental/paginated and do not add a visible near-sea toggle unless requested. The route sends the initial page plus result metadata marked as a partial catalog; the client fetches bounded filtered pages when an interaction needs more results or broader filtering.
components/villas/detail Villa detail page/helpers/gallery shell, gallery grid, gallery lightbox, gallery tile components, gallery URL/proxy helpers, intro, amenities UI helpers, policy section, booking sidebar, booking calendar UI/visual helpers, recommendations, layout renderer/helpers/parts, detail skeletons, and review videos backed by lib/villas/detail embed URLs. components/villas/listing Shared villa cards, price display, stats, amenities, grids, listing skeletons. Home, search, and recommendations should reuse these shared listing components. Villa detail card links intentionally use normal document navigation to avoid extra RSC /_rsc Worker requests in high-traffic public flows.
components/layout Public header, footer, shared public contact section, mobile bottom contact actions, contact icons, theme provider. Contact actions and the shared contact section should be backed by lib/site-contact.ts and site settings.
components/guides Public guide list/detail pages, guide content rendering, and guide-to-villa recommendation surfaces. Keep public guide pages article-focused, use normal document navigation for guide cards in high-traffic public rails/lists, and reuse components/villas/listing for recommended villa cards.
components/legal Public legal page renderer for Terms and Privacy content blocks. Render only supported structured text blocks and safe links; do not use raw HTML for admin-managed legal content.
components/admin Admin shell, browser admin token helper, shared admin API response helpers, shared admin feedback, shared admin loading skeletons, settings editor, section editor, guide editor, legal page editor, detail layout editor, login form. Keep admin screens compact, Thai-facing, consistent with settings/sections UX patterns, route loading shells, shared save/error feedback that scrolls into view, shared browser error/payload helpers in components/admin/admin-api-client.ts, and redirect unauthenticated browser sessions to /admin/login.
components/ui Small generic UI primitives such as skeletons, dropdown selects, and the shared restricted YouTube embed. Only place components here when they are truly generic across public/admin features.

worker.js, worker-cache-policy.js, worker-html-cache-version.js, and scripts/prewarm-public-html.mjs Cloudflare Worker wrapper around OpenNext output. A conservative 6-hour public HTML micro-cache uses Cloudflare Cache API for allowlisted cookie-free, query-free HTML requests only: /, /search, /guides, /guides/:slug, /terms, and /privacy; /villas/:id uses the same allowlist rules with a 24-hour HTML cache. It bypasses admin, API, /_next, RSC/prefetch variant headers, cookies, query strings, non-HTML requests, and responses with Set-Cookie. Cache keys include the Cloudflare Worker CF_VERSION_METADATA deployment id plus CMS/data version groups such as site-settings, home-sections, guides, legal-pages, detail-layout, villa-details, and villa-images; the Worker reads CMS versions from a future BPV_HTML_CACHE_VERSIONS KV binding when present and falls back to NEXT_INC_CACHE_R2_BUCKET under the html-cache-versions/ prefix. The post-deploy prewarm script fetches the same allowlisted HTML routes with document Accept headers, requires an explicit target host from --url, BPV_PREWARM_BASE_URL, or NEXT_PUBLIC_SITE_URL, keeps fixed public pages first, reads bounded dynamic villa/guide paths from /sitemap.xml, applies bounded fetch timeouts, and can verify MISS responses with a follow-up HIT request. Hashed Next static assets under /_next/static/ receive a 1-year immutable browser cache header from the Worker. A separate 1-year image edge cache handles cookie-free display proxy GET requests for /api/villas/:id/images?url=..., /api/houses/images/proxy?url=..., /api/site-assets/proxy?url=..., and /api/guides/images/proxy?url=..., validates allowlisted w/q transform variants, keys cached image responses by source URL plus width, quality, and negotiated avif/webp/original format from the request Accept header, and stores only successful image/* responses without Set-Cookie. Public image URL builders and proxy route allowlists canonicalize HTTPS URLs and reject credentials, localhost, loopback, private, and link-local literal hosts before proxying. A JSON edge cache handles cookie-free public JSON APIs for /api/houses, /api/home-sections, /api/villas/:id, /api/villas/:id/booking-calendar?month=YYYY-MM, and query-free /api/villas/:id/images responses when they are successful application/json; /api/houses uses a 6-hour JSON cache while the other allowlisted public JSON APIs keep the default 12-hour JSON cache. Booking calendar cache keys preserve the validated month query; other query variants bypass. Keys include the Worker deployment version plus home-sections, villa-listings, villa-details, or villa-images version groups as relevant. The Next image optimizer is disabled globally in next.config.ts; any remaining /_next/image header handling here is fallback behavior, not the normal public image path. Run worker-cache-policy.test.ts, worker-html-cache-version.test.ts, scripts/prewarm-public-html.test.ts, lib/cache-revalidation.test.ts, lib/__tests__/public-image-proxy.test.ts, lib/villas/__tests__/image-proxy.test.ts, lib/villas/__tests__/cover-image-proxy.test.ts, lib/site-settings/__tests__/asset-proxy.test.ts, lib/guides/__tests__/image-proxy.test.ts, components/villas/detail/__tests__/gallery.test.tsx, components/villas/listing/__tests__/villa-card-navigation.test.tsx, components/villas/home/__tests__/hero-section.test.tsx, components/villas/home/__tests__/destinations-section.test.tsx, components/villas/home/__tests__/page.test.tsx, components/guides/__tests__/guide-request-budget.test.tsx, components/guides/__tests__/guide-detail-page.test.tsx, lib/__tests__/next-config.test.ts, and production network checks that public pages do not request /_next/image. After Worker deploy, verify x-bpv-html-cache transitions from MISS to HIT for allowlisted pages and stays BYPASS for RSC, cookie, query, admin, and API requests; verify x-bpv-image-cache transitions from MISS to HIT for display proxy images and keeps separate variants for different w/q/Accept combinations; verify x-bpv-json-cache transitions from MISS to HIT for allowlisted public JSON APIs and stays BYPASS for cookie, query, or non-JSON variants.
lib/cache-revalidation.ts and lib/html-edge-cache-version.ts Shared tag revalidation helpers. Supabase CMS helpers for settings, home sections, guides, legal pages, TikTok, and detail layout are tag-only for Next data cache, then bump the matching Cloudflare HTML cache version group through OpenNext Cloudflare bindings.
