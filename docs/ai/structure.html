Baan Pool Villa AI Structure Map

This document is the source of truth for repository structure, ownership, and common data flow. Use AGENTS.md for rules and this file for where things live.

Last reviewed: 2026-06-12. Next.js App Router route groups such as (home), (public), and (admin) do not appear in the public URL.

Maintenance Triggers

Update this file in the same change when any of these happen:

  • A route, route group, loading UI, not-found UI, or route handler is added, moved, renamed, or removed.
  • A feature folder, shared component family, shared helper module, or ownership boundary changes.
  • A new site setting, CMS table, Supabase migration pattern, public data contract, or admin API flow is introduced.
  • Cache tags, cache durations, revalidation paths, SEO helpers, contact helpers, pricing helpers, or image URL ownership changes.
  • The recommended targeted tests for a feature area change.

Top-Level Map

Path Role Notes
app/ Next.js App Router routes and route handlers Route files should stay thin and delegate UI/data logic to feature modules.
components/ Public, admin, layout, and small UI components Feature UI belongs in its feature folder; avoid top-level villa re-export wrappers.
lib/ Data access, normalization, validation, settings, SEO, cache, pricing, and shared helpers Prefer these helpers over ad hoc constants or duplicated transforms in components.
supabase/ Schema migrations and seed data Migrations are source-controlled history; online project changes need minimal idempotent patch SQL.
next.config.ts Next.js build/runtime configuration Image config keeps allowed remote hosts documented, uses the custom image loader from lib/aws-loader.ts instead of the built-in Next image optimizer, and applies the sitemap response cache header. AWS-origin sources and s3.ap-southeast-1.amazonaws.com/poolvillas.co.ltd objects receive width/quality transform params through the AWS loader; other validated HTTPS sources load directly with width/quality query params so current external catalog and CMS images do not break.
tests/ End-to-end and production smoke tests Unit and component tests usually live beside the touched feature in __tests__.
docs/ Agent specs, plans, and AI-facing structure docs This file lives at docs/ai/structure.html.

App Router Map

Root Files

Path URL Responsibility
app/layout.tsx All routes Root HTML/body shell, site-settings-backed global metadata/icon links/Google Tag Manager script rendering, global CSS/font wiring, and revalidate = 0 so rendered App Router pages are produced on demand while explicit data caches remain tagged and time-based.
app/sitemap.ts /sitemap.xml Public sitemap using villa, guide CMS, legal page CMS, and site URL helpers. The sitemap response keeps a 24-hour route cache with revalidate = 86400 and a sitemap-specific Cache-Control header from next.config.ts; underlying villa, guide, and legal page reads keep their tagged data caches. Dynamic villa source failures should fail the sitemap route; guide or legal CMS failures can return a partial sitemap with static and villa routes so CI/build environments without CMS env do not fail. lastModified should only be emitted where upstream data has a trustworthy timestamp.
app/robots.ts /robots.txt Robots configuration.
app/globals.css All routes Tailwind v4 global styles and shared theme variables.

Public Routes

Path URL Delegates To

The route starts homepage data before awaiting site settings, then streams the settings-backed hero shell first while the hero search and deferred homepage content resolve behind Suspense from the shared homepage data promise; guide loading no longer blocks the bounded villa catalog read, and hero search price/zone controls use static options from lib/villas/search-options.ts instead of deriving facets from the fetched villa window. The server route still uses full site settings for metadata and JSON-LD, but the client HomePage receives only the rendered homepage settings fields (heroImage, tiktok, contact, and bank), public guide summaries, and homepage public villa listing DTOs loaded from the home-section-config-sized listing window plus active configured home-section house IDs with validated image source URLs for the custom image loader; guides, villas, and TikTok videos are capped before crossing into the client payload. The homepage uses the CMS SEO title as an absolute title so the root metadata template does not duplicate the site name, and it passes non-visible degraded source data when guide posts, homepage villa listings, home sections, or site settings fall back or fail independently, with non-settings degraded sources emitted by the deferred content stream.
app/(public)/(home)/loading.tsx / loading UI components/villas/home/loading-skeleton.
app/(public)/search/page.tsx /search components/villas/search/page, villa listing helpers, static search options, landing first-page search metadata, and site-settings-backed public SEO defaults. The route resolves metadata through the search section SEO template before falling back to global SEO. Query-string filtering is applied to the first server-loaded page through bounded Supabase search helpers, while price max/default and zone options come from lib/villas/search-options.ts; the client requests additional bounded filtered pages from /api/houses when an interaction needs more results, so neither the route nor the public API exposes the full catalog in one response.
app/(public)/search/loading.tsx /search loading UI components/villas/search/search-loading-skeleton.
app/(public)/guides/page.tsx /guides components/guides/guide-list-page, guide CMS server reads, SEO helpers, and site-settings-backed share defaults. The rendered page is on demand while guide and settings reads use tagged data caches; it resolves metadata through the guides section SEO template before falling back to global SEO, renders guide covers through next/image with the custom image loader, and renders an empty guide list instead of failing when the guide CMS is unavailable.
app/(public)/guides/[slug]/page.tsx /guides/:slug components/guides/guide-detail-page, guide CMS server reads, villa listing recommendations, SEO/JSON-LD helpers, and lazy YouTube posters that mount restricted embeds after play. app/(public)/guides/[slug]/not-found.tsx /guides/:slug missing guide UI Guide detail not-found experience using the shared generic public not-found layout.
app/(public)/terms/page.tsx and app/(public)/privacy/page.tsx /terms, /privacy components/legal/legal-page, lib/legal-pages/server.ts, site settings, and lib/seo.ts. Rendered output is on demand while legal page reads use tagged data caches; missing or unavailable CMS rows fall back to safe defaults.
app/(public)/terms/loading.tsx and app/(public)/privacy/loading.tsx /terms, /privacy loading UI Route-local legal document skeletons using public theme variables.
app/(public)/villas/[id]/page.tsx /villas/:id components/villas/detail/page, listing/detail API data, SEO/JSON-LD helpers, site web style settings, up to four display-prioritized SSR Supabase gallery preview images, and a client gallery loader backed by /api/villas/:id/images. Villa detail pages are not prebuilt with generateStaticParams; rendered output is on demand, cached initial data comes from villa listing/detail, villa-image, and site-web-style tags, SSR preloads only the above-the-fold gallery preview images selected with the same main/side priority used by the rendered gallery, uploaded per-villa cover overrides become the first large gallery image and suppress old cover rows while present, the client defers the full gallery image-set request until browser idle or user gallery interaction, and the Gallery style chooses direct lightbox or a categorized natural-ratio JavaScript masonry overview whose image selection continues into the same lightbox and returns to the overview on close. The masonry layout measures loaded images in the browser, keeps DOM order, uses equal responsive gaps, and does not require stored image dimensions. Optional Gallery background/text colors apply to villa and activity-image modals, while empty color values inherit theme tokens. Lower detail blocks defer rendering until they approach the viewport, recommended villas load client-side from /api/home-sections after the recommendation block approaches the viewport, cached advertisements load only when the CMS detail layout contains the advertisement block, categorized image previews render placeholder tiles until their block approaches the viewport, public detail payloads pass validated listing cover and gallery source URLs to next/image with the custom image loader, gallery downloads use /api/villas/:id/images?download=1, and the route renders VacationRental plus breadcrumb JSON-LD.
app/(public)/villas/[id]/loading.tsx /villas/:id loading UI components/villas/detail/detail-page-skeleton.
app/(public)/villas/[id]/not-found.tsx /villas/:id missing villa UI Villa-specific not-found experience using the shared public not-found layout with search and home actions.
app/(public)/[...legacy]/page.tsx Unmatched public legacy paths Safe legacy villa redirect fallback. App Router only reaches this catch-all after concrete routes fail to match; the route reads the final path segment, accepts positive numeric villa ids only, verifies the villa through getListingById, permanently redirects existing villas to /villas/:id, and returns notFound() for non-numeric or unknown ids.
app/(public)/[...legacy]/not-found.tsx Unmatched public legacy paths that do not redirect Generic public not-found experience for invalid or unknown legacy paths.
