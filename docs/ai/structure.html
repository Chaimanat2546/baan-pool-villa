Baan Pool Villa AI Structure Map

This document is the source of truth for repository structure, ownership, and common data flow. Use AGENTS.md for rules and this file for where things live.

Last reviewed: 2026-06-09. Next.js App Router route groups such as (home), (public), and (admin) do not appear in the public URL.

Maintenance Triggers

Update this file in the same change when any of these happen:

  • A route, route group, loading UI, not-found UI, or route handler is added, moved, renamed, or removed.
  • A feature folder, shared component family, shared helper module, or ownership boundary changes.
  • A new site setting, CMS table, Supabase migration pattern, public data contract, or admin API flow is introduced.
  • Cache tags, cache durations, revalidation paths, SEO helpers, contact helpers, pricing helpers, or image URL ownership changes.
  • The recommended targeted tests for a feature area change.

Top-Level Map

Path Role Notes
app/ Next.js App Router routes and route handlers Route files should stay thin and delegate UI/data logic to feature modules.
components/ Public, admin, layout, and small UI components Feature UI belongs in its feature folder; avoid top-level villa re-export wrappers.
lib/ Data access, normalization, validation, settings, SEO, cache, pricing, and shared helpers Prefer these helpers over ad hoc constants or duplicated transforms in components.
supabase/ Schema migrations and seed data Migrations are source-controlled history; online project changes need minimal idempotent patch SQL.
next.config.ts Next.js build/runtime configuration Image config keeps allowed remote hosts documented, disables the Next image optimizer globally so public images do not consume /_next/image transformations on Cloudflare Free, and applies the sitemap response cache header.
tests/ End-to-end and production smoke tests Unit and component tests usually live beside the touched feature in __tests__.
docs/ Agent specs, plans, and AI-facing structure docs This file lives at docs/ai/structure.html.

App Router Map

Root Files

Path URL Responsibility
app/layout.tsx All routes Root HTML/body shell, global metadata base, global CSS/font wiring, and revalidate = 0 so rendered App Router pages are produced on demand while explicit data caches remain tagged and time-based.
app/sitemap.ts /sitemap.xml Public sitemap using villa, guide CMS, legal page CMS, and site URL helpers. The sitemap response keeps a 12-hour route cache with revalidate = 43200 and a sitemap-specific Cache-Control header from next.config.ts; underlying villa, guide, and legal page reads keep their tagged data caches. Dynamic villa source failures should fail the sitemap route; guide or legal CMS failures can return a partial sitemap with static and villa routes so CI/build environments without CMS env do not fail. lastModified should only be emitted where upstream data has a trustworthy timestamp.
app/robots.ts /robots.txt Robots configuration.
app/globals.css All routes Tailwind v4 global styles and shared theme variables.

Public Routes

Path URL Delegates To
app/(public)/layout.tsx Public shell components/layout, resolved site settings, theme variables, contact config. The shell inherits root on-demand rendering and must not force force-dynamic because that would turn explicit data caches into no-store fetches.
app/(public)/(home)/page.tsx / components/villas/home/page, lib/seo.ts, lib/json-ld.ts; rendered output is on demand while guide, villa catalog, home-section, and site-settings reads come from tagged data caches. The homepage uses the CMS SEO title as an absolute title so the root metadata template does not duplicate the site name, and it passes non-visible degraded source data when guides, villa catalog, home sections, or site settings fall back or fail independently.
app/(public)/(home)/loading.tsx / loading UI components/villas/home/loading-skeleton.
app/(public)/search/page.tsx /search components/villas/search/page, villa listing helpers, landing first-page search metadata, and site-settings-backed public SEO defaults. The route resolves metadata through the search section SEO template before falling back to global SEO. Query-string filtering is intentionally not performed by the server route; the client reads the current URL, hydrates the full catalog through /api/houses when a deep link has search criteria, and filters/sorts in the browser to reduce Cloudflare Worker CPU and RSC request cost.
app/(public)/search/loading.tsx /search loading UI components/villas/search/search-loading-skeleton.
app/(public)/guides/page.tsx /guides components/guides/guide-list-page, guide CMS server reads, SEO helpers, and site-settings-backed share defaults. The rendered page is on demand while guide and settings reads use tagged data caches; it resolves metadata through the guides section SEO template before falling back to global SEO, and it renders an empty guide list instead of failing when the guide CMS is unavailable.
app/(public)/guides/[slug]/page.tsx /guides/:slug components/guides/guide-detail-page, guide CMS server reads, villa listing recommendations, SEO/JSON-LD helpers, and lite YouTube posters that defer third-party player iframes until play. Guide detail pages are not prebuilt with generateStaticParams; rendered output is on demand, cached data comes from guide/villa tags, the route renders Article plus breadcrumb JSON-LD, and admin saves invalidate guide CMS data tags only.
app/(public)/terms/page.tsx and app/(public)/privacy/page.tsx /terms, /privacy components/legal/legal-page, lib/legal-pages/server.ts, site settings, and lib/seo.ts. Rendered output is on demand while legal page reads use tagged data caches; missing or unavailable CMS rows fall back to safe defaults.
app/(public)/terms/loading.tsx and app/(public)/privacy/loading.tsx /terms, /privacy loading UI Route-local legal document skeletons using public theme variables.
app/(public)/villas/[id]/page.tsx /villas/:id components/villas/detail/page, listing/detail API data, first resolved home-section recommendations, SEO/JSON-LD helpers, and a client gallery loader backed by /api/villas/:id/images. Villa detail pages are not prebuilt with generateStaticParams; rendered output is on demand, cached data comes from villa listing/detail and home-section tags, SSR should not preload Supabase gallery rows, initial client mount loads the full image set once to fill the visible gallery grid, and the route renders VacationRental plus breadcrumb JSON-LD.
app/(public)/villas/[id]/loading.tsx /villas/:id loading UI components/villas/detail/detail-page-skeleton.
app/(public)/villas/[id]/not-found.tsx /villas/:id missing villa UI Detail not-found experience.

Admin Route Handlers

Shared admin bearer-token checks, mutation origin checks, and Supabase-style error responses live in lib/admin/route-helpers.ts and lib/admin/request-origin.ts. Keep route handlers focused on request parsing, validation, persistence, and cache invalidation.

Path URL Primary Responsibility
app/(admin)/api/admin/home-sections/route.ts /api/admin/home-sections Admin auth, parse/validate home section configs, persist to Supabase, revalidate home cache.
app/(admin)/api/admin/home-sections/preview/route.ts /api/admin/home-sections/preview Validate manual home section house IDs without persisting or returning real listing details to the admin prototype preview.
app/(admin)/api/admin/site-settings/route.ts /api/admin/site-settings Admin auth through the shared bearer-token and mutation-origin guard, validate site settings (excluding TikTok fields), handle asset uploads, persist settings, and revalidate public settings cache. app/(admin)/api/admin/guides/route.ts /api/admin/guides Admin auth, parse/validate guide drafts, generate unique slugs, persist guide posts, revalidate guide cache.

app/(admin)/api/admin/legal-pages/route.ts /api/admin/legal-pages Admin auth, load fixed legal page records, parse/validate legal page drafts, persist to Supabase, and revalidate legal page cache tags only.

Component Ownership

Path Owns Reuse Notes
components/villas/home Home page sections, CMS-driven home assembly, hero/contact/articles/destination sections, TikTok block renderer (settings-driven, first-6 thumbnail preview with click-to-load player), villa rails, home skeletons, and minimal homepage client payloads. Use VillaRail, home shared helpers, and section header patterns before creating new section UI. The homepage server may use the full villa catalog to resolve sections, but the client receives only filterSummary, destinationVillas, and resolved home sections rather than the full catalog.
components/admin/tiktok TikTok account/video settings manager with add/delete/reorder controls, URL-only input handling, and homepage preview/status messaging for first-6 video usage. Render edits as draft-local previews until save; keep settings contract aligned to lib/site-settings.
components/villas/search Search page, search bar, filters, mobile filter drawer, search loading skeleton, first-page server result hydration, and on-demand catalog hydration through /api/houses. Keep results incremental/paginated and do not add a visible near-sea toggle unless requested. The route sends the initial filtered page plus result metadata marked as a partial catalog; the client fetches the full catalog only when an interaction needs more results or broader filtering.
components/villas/detail Villa detail page, gallery, intro, booking sidebar, recommendations, layout renderer, detail skeletons, and review video posters backed by lib/villas/detail thumbnail URLs. Use detail layout blocks/renderers for admin-managed layout surfaces. Review videos should render thumbnail posters first and mount YouTube iframes only after play.
components/villas/listing Shared villa cards, price display, stats, amenities, grids, listing skeletons. Home, search, and recommendations should reuse these shared listing components. Villa detail card links intentionally use normal document navigation to avoid RSC /_rsc worker requests on Cloudflare Free.
components/layout Public header, footer, mobile bottom contact actions, contact icons, theme provider. Contact actions should be backed by lib/site-contact.ts.
components/guides Public guide list/detail pages, guide content rendering, and guide-to-villa recommendation surfaces. Keep public guide pages article-focused and reuse components/villas/listing for recommended villa cards.
components/legal Public legal page renderer for Terms and Privacy content blocks. Render only supported structured text blocks and safe links; do not use raw HTML for admin-managed legal content.
components/admin Admin shell, browser admin token helper, shared admin loading skeletons, settings editor, section editor, guide editor, legal page editor, detail layout editor, login form. Keep admin screens compact, Thai-facing, consistent with settings/sections UX patterns, route loading shells, and redirect unauthenticated browser sessions to /admin/login.
components/ui Small generic UI primitives such as skeletons and dropdown selects. Only place components here when they are truly generic across public/admin features.

Path Owns Important Tests

lib/home-sections Admin-managed home section config types, validation, Supabase persistence, server reads, section resolution. lib/home-sections/__tests__
lib/site-settings Site identity, theme colors, logo/hero assets, global SEO, section SEO templates, contact/TikTok settings, defaults, validation, Supabase reads, retention. lib/site-settings/__tests__
lib/tiktok TikTok public embed metadata helpers, including server-side oEmbed thumbnail resolution for homepage previews. lib/tiktok/__tests__
lib/detail-layout Admin-managed detail layout types, defaults, validation, compatibility, versioned layout definitions. lib/detail-layout/__tests__
lib/guides Guide CMS types, defaults, slug/validation helpers, Supabase server reads, recommendation ordering, admin API tests. lib/guides/__tests__
lib/legal-pages Legal page CMS types, defaults, validation, cached public server reads, admin API tests, and fixed terms/privacy slug ownership. lib/legal-pages/__tests__
lib/cache-policy.ts Data cache durations, cache tags, and public API Cache-Control headers. Public villa, guide, legal page, home-section, site-settings, image, and embed reads use a 12-hour TTL; rendered pages do not keep route-level TTL constants, while sitemap.xml intentionally keeps a 12-hour route cache and response cache header to reduce crawler Worker requests. lib/__tests__/cache-policy.test.ts
worker.js Cloudflare Worker wrapper around OpenNext output. The Next image optimizer is disabled globally in next.config.ts; any remaining /_next/image header handling here is fallback behavior, not the normal public image path. Run lib/__tests__/next-config.test.ts and production network checks that public pages do not request /_next/image.
lib/cache-revalidation.ts Shared tag revalidation helpers. Supabase CMS helpers for settings, home sections, guides, legal pages, TikTok, and detail layout are tag-only; external villa refresh also expires only data tags and does not call revalidatePath. lib/cache-revalidation.test.ts
lib/seo.ts and lib/json-ld.ts Metadata, canonical URL support, site-settings-backed public metadata defaults, admin-managed meta keywords, villa-detail keyword derivation from listing data, legal page metadata, absolute-title handling, breadcrumb/home JSON-LD builders, and safe JSON-LD serialization. lib/__tests__/seo.test.ts, lib/__tests__/json-ld.test.ts
lib/site-contact.ts Public contact actions and link formatting from site settings/contact defaults. Update focused tests when contact settings are added or changed.
lib/admin Admin authentication/config helpers, mutation request origin checks, and shared admin route auth/error response utilities. Successful admin bearer checks use a short in-memory TTL cache keyed by a token hash; failed checks are not cached. Admin POST, PUT, and DELETE requests allow missing Origin, the configured NEXT_PUBLIC_SITE_URL origin, the request host, and localhost origins in development. lib/admin/__tests__ plus targeted admin API route tests around auth, mutation origin checks, and Supabase error behavior.

Primary Data Flow

Flow Source Normalization/Cache Consumers
Villa listings https://www.devillegroups.com/api/json/getHouse_deville.json lib/villas/server.ts, lib/villas/normalize.ts, listing cache tag; the normalized catalog result is cached with the same villa listings TTL/tag so routes do not re-parse the full external catalog on warm reads. Home rails, search results, first home-section detail recommendations, guide recommendations, sitemap, public houses API.
Villa detail Deville Central accommodation API with DEVILLE_BEARER_TOKEN. lib/villas/server.ts, lib/villas/detail.ts, detail cache tag. Villa detail route and public villa detail API.
Villa images Supabase image rows matched by images.property_id to villa id. lib/villas/images.ts, image host builder, shared villa-images tag, and per-villa image cache tag. Public villa images API and the villa detail client gallery loader; detail SSR keeps gallery rows outside the critical path, then initial client mount loads the full image set once so the visible gallery and lightbox categories have complete data.
Home sections Supabase home-section CMS project. lib/home-sections/server.ts, validation/resolve helpers, home sections cache tag. Results include source, degraded, and an optional fallback reason so callers can distinguish intentional empty-config fallback from config-load failure fallback. Home page, villa detail recommendations from the first resolved section, and admin sections editor.
Site settings Supabase settings table with defaults fallback. lib/site-settings/server.ts, defaults, validation, colors, retention, site settings cache tag. Load results include source and degraded; global and section SEO templates plus page-specific keyword arrays are normalized here, TikTok homepage settings flow directly to the client renderer, and thumbnail hydration uses client-side TikTok oEmbed caching so the homepage route does not wait on TikTok oEmbed. Public/admin layouts, theme provider, metadata, contact actions, dedicated TikTok admin manager (/admin/tiktok), general settings editor, and homepage section composition.
Detail layout settings Supabase detail layout config. lib/detail-layout, admin detail layout API, detail layout cache revalidation. Villa detail renderer and admin detail layout builder.
Guide CMS Supabase guide_posts, guide_asset_uploads, and public guide-assets storage bucket. lib/guides, guide cache tags, slug validation, admin guide APIs. Public guide reads throw on CMS/config failures and return empty/null only for true empty list or missing slug outcomes. Public guide list/detail pages, homepage guide article rail, admin guide editor, sitemap guide URLs.
Legal pages Supabase legal_pages fixed records for terms and privacy. lib/legal-pages, legal page cache tags, fixed-slug validation, and admin legal page API. Public legal reads fall back to safe defaults when CMS rows are missing or unavailable. Public /terms and /privacy pages, footer legal links, sitemap legal URLs, and admin legal page editor.

Model Workflow Map

Use these Codex workspace model names when model selection is available: GPT-5.5, GPT-5.4, GPT-5.4-Mini, and GPT-5.3-Codex-Spark. If model switching is unavailable, continue with the current model and compensate with fact checks, targeted tests, lint, build, and review.

Task-Based Model Selection

Task Type Planning / Analysis Implementation Review / Escalation
Ordinary UI: navbar, cards, responsive layout, bottom nav, colors, spacing GPT-5.4-Mini with Low or Medium, or GPT-5.4 with Medium GPT-5.4-Mini or GPT-5.4 for scoped edits Escalate to GPT-5.4 if visual behavior becomes cross-component or responsive bugs are unclear.
Next.js, Supabase, API routes, routing, image gallery, search filters GPT-5.4 with High GPT-5.3-Codex-Spark with Medium or High after the plan is clear Escalate to GPT-5.5 when route behavior, cache, auth, or data contracts become risky.
Data contracts, pricing, normalization, site settings, admin APIs, RLS GPT-5.5 with High GPT-5.3-Codex-Spark with High only after approval and small-step breakdown GPT-5.5 with Extra High for final review.
Hard bugs: hydration mismatch, SSR, Suspense, Supabase policy, deploy failures GPT-5.5 with Extra High for root-cause analysis GPT-5.3-Codex-Spark with High to fix one confirmed issue at a time Return to GPT-5.5 if the symptom changes, tests fail repeatedly, or evidence contradicts the theory.
Small docs, copy, README, file inventory GPT-5.4-Mini with Low GPT-5.4-Mini with Low Manual diff/read-through is usually enough unless docs describe executable behavior.

Workflow Step Model Selection

Step Work Recommended Model Reasoning
1 Clarify outcome, flow, constraints GPT-5.4-Mini for simple work, GPT-5.4 for serious work Low / Medium
2 Inspect codebase, existing patterns, helpers, docs GPT-5.3-Codex-Spark for quick inventory, GPT-5.4 for pattern interpretation Medium
3 Read and interpret Next.js docs in node_modules GPT-5.4 Medium / High
4 Propose 2-3 approaches with trade-offs GPT-5.5 High
5 Re-check approach and request approval GPT-5.5 for risky work, otherwise GPT-5.4 Medium / High
6 Write implementation plan and test strategy GPT-5.5 for system/API/data, GPT-5.4 for ordinary UI High
7 Write or update tests GPT-5.4, or GPT-5.3-Codex-Spark for narrow tests Medium / High
8 Implement incrementally GPT-5.3-Codex-Spark after the plan is clear; escalate to GPT-5.4 or GPT-5.5 for coupling or risk Medium / High
9 Run tests, quality checks, and final review GPT-5.4 for normal work, GPT-5.5 for risky work High / Extra High

Spark Guardrail

GPT-5.3-Codex-Spark is for fast, narrow, incremental edits after a plan exists. Escalate back to GPT-5.4 or GPT-5.5 if ownership is unclear, behavior spans multiple modules, tests fail repeatedly, or the change risks public data, auth, pricing, settings, cache, or Supabase behavior.
