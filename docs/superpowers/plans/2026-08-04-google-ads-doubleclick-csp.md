# Google Ads DoubleClick CSP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Permit only the Google Ads request origins observed in production CSP errors, in only the required CSP directives.

**Architecture:** Keep `lib/security/csp.ts` as the single source of truth. Add named origin constants, include them in `connectSources` and `imageSources` according to the captured browser evidence, and verify both the CSP builder and the global header generated by `next.config.ts`.

**Tech Stack:** TypeScript, Next.js 16 headers configuration, Vitest

## Global Constraints

- Use exact HTTPS origins; do not introduce wildcard advertising domains.
- Do not change GTM configuration, consent behavior, scripts, frames, or unrelated CSP directives.
- Preserve all unrelated working-tree changes.
- Do not commit unless the user explicitly requests it.
