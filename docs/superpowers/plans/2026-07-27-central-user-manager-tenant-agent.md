# Central User Manager Tenant Agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** เพิ่ม Tenant Agent ที่มีขอบเขตแคบใน `baan-pool-villa` เพื่อให้ Central Control Plane จัดการเฉพาะบัญชีแอดมินของ Supabase โปรเจกต์นั้นได้อย่างปลอดภัย พร้อมบังคับเปลี่ยน temporary password, ระงับ session เดิมด้วย credential fencing และรองรับการกู้คืนจาก partial failure โดยไม่เก็บรหัสผ่าน

**Architecture:** แต่ละ deployment ของ `baan-pool-villa` ถือ `sb_secret_...` ของ Supabase โปรเจกต์ตัวเองเท่านั้น และเปิด internal API สอง endpoint หลัง Cloudflare Access. ทุกคำขอต้องผ่าน Access JWT และ Ed25519 signature ก่อนเข้า operation state machine ที่ใช้ durable intent, per-email lease, fence version และ quarantine. การบังคับเปลี่ยนรหัสผ่านใช้เส้นทางภายใน tenant เดียวกันและ version fence ชุดเดียวกับ Central operation.

**Tech Stack:** Next.js 16.2 App Router, React 19, TypeScript 6, Supabase Auth/Postgres, Cloudflare Workers/OpenNext, Web Crypto Ed25519/SHA-256, Vitest.

## Fixed Protocol Contract

ใช้ค่าคงที่เดียวกันใน Tenant Agent และ Control Plane:

```text
X-CUM-Version: 1
X-CUM-Key-Id: <active signing key id>
X-CUM-Tenant-Id: <UUID from customer_projects.id>
X-CUM-Operation-Id: <UUID generated by browser>
X-CUM-Timestamp: <Unix epoch seconds>
X-CUM-Actor-Uid: <webook auth.users.id>
X-CUM-Body-Sha256: <lowercase hex SHA-256 of exact request bytes>
X-CUM-Signature: <base64 Ed25519 signature>
```

Canonical bytes are UTF-8 without a trailing newline:

```text
CUM1
<UPPERCASE METHOD>
<exact pathname only>
<tenant id>
<operation id>
<timestamp>
<actor uid>
<body sha256>
```

Rules:

- Timestamp window is ±60 seconds.
- Tenant ID must equal `CENTRAL_USER_MANAGER_TENANT_ID`.
- Path must be one of the two exact paths in this plan; no redirect and no alternate slash.
- The target reads the body once as bytes, hashes those exact bytes, then parses JSON.
- Access JWT comes from `Cf-Access-Jwt-Assertion`; validate signature, issuer, audience, `exp`, and `common_name === CENTRAL_USER_MANAGER_ACCESS_CLIENT_ID`. For service-token JWT, an empty `sub` is valid.
- Ed25519 public keys are server-only configuration keyed by `X-CUM-Key-Id`; unknown or retired key IDs fail closed.

Operation request:

```ts
export type CentralUserAction =
  | "list_users"
  | "create_user"
  | "reissue_temporary_password"
  | "suspend_user"
  | "reactivate_user";

export interface CentralUserOperationRequest {
  action: CentralUserAction;
  payload:
    | { page: number; pageSize: number }
    | { email: string };
}
```

`pageSize` is `1..100`. Mutating actions accept only `email`. Temporary password is generated inside the Tenant Agent and returned only on the first successful response of `create_user`, `reissue_temporary_password`, or `reactivate_user`. A retry of a completed operation never returns the earlier password.

## Rollout Invariant

Roll out each tenant in this order:

1. Apply prepare migration.
2. Deploy Agent with `CENTRAL_USER_MANAGER_AGENT_ENABLED=false` and `CENTRAL_USER_MANAGER_CREDENTIAL_FENCE_ENABLED=false`.
3. Run exact preflight and Auth metadata backfill.
4. Apply enforcement migration.
5. Enable credential fence, test existing admin sign-in again, then enable Agent.
6. Register and activate the tenant in webook only after health and a non-mutating list operation pass.

Never apply the enforcement migration before every active legacy admin has matching Auth `app_metadata.credential_version = 1`.

## Tenant Acceptance Gate

The Tenant Agent is ready for a tenant only when all are true:

- Prepare and enforcement migrations are recorded and applied in the required order.
- No normalized-email conflict or one-sided Auth/profile record remains.
- Every active legacy admin has matching Auth and DB credential version.
- Existing session access is denied after a version bump even though its access JWT has not expired.
- No operation/audit row contains a password or token.
- A completed-operation retry cannot recover the original temporary password.
- Quarantine survives lease expiry and blocks later mutations until reviewed transfer.
- Health returns matching tenant/project/version/attestation values.
- Cloudflare Access and Ed25519 verification each independently fail closed.
- Target UI forces password change and requires a fresh login afterward.
- Full tests, lint, build, desktop/mobile inspection, and staging fault matrix pass.
